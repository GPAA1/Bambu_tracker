# Bambu Tracker — учёт расхода пластика для 3D-принтеров

Программа слушает MQTT-сообщения от 3D-принтеров Bambu Lab (или от локального
симулятора), автоматически записывает каждую печать в Google-таблицу
(«Лог печати»), сверяет расход материала с остатками на складе («Склад») и
предупреждает, если пластика не хватает.

Этот README проведёт вас через весь путь: от создания Google-таблицы и
получения ключа до первого тестового запуска и перехода на реальные принтеры.

## 1. Как это устроено

- Каждый принтер Bambu Lab публикует состояние печати по протоколу **MQTT**
  в топик `device/<серийный_номер>/report`.
- `tracker.py` подписывается на эти топики, ловит сообщения о старте печати
  (`gcode_state = RUNNING`), достаёт название файла, номер заявки и список
  использованных материалов (AMS) и:
  - дописывает строку в лист **«Лог печати»**;
  - сверяет расход с остатком на листе **«Склад»** и, если материала не
    хватает, пишет предупреждение в лог.
- Список принтеров (имя, IP, Access Code, серийный номер) программа читает
  из листа **«Принтеры»** — то есть добавлять принтеры можно прямо в
  Google-таблице, без изменения кода.
- Есть два режима работы:
  - **Тестовый (test_mode = true)** — принтеры не нужны, вместо них скрипт
    `mock_printers.py` шлёт случайные «печати» на локальный MQTT-брокер.
  - **Боевой (test_mode = false)** — программа подключается напрямую к
    реальным принтерам по Wi-Fi/LAN.

## 2. Что нужно установить

| Компонент | Зачем | Где взять |
|---|---|---|
| **Python 3.9+** | сама программа | https://www.python.org/downloads/ (при установке отметьте «Add python.exe to PATH») |
| **pip-пакеты**: `paho-mqtt`, `gspread` | MQTT-клиент и работа с Google Sheets | ставятся командой ниже |
| **tkinter** | графический интерфейс | входит в стандартный Python на Windows; на Linux иногда нужно доустановить (`sudo apt install python3-tk`) |
| **MQTT-брокер (Mosquitto)** | нужен **только для тестового режима** | https://mosquitto.org/download/ |
| **Google-аккаунт** | для создания таблицы и сервисного ключа | — |

Установка Python-пакетов (в терминале / командной строке):

```bash
pip install paho-mqtt gspread
```

## 3. Шаг 1. Создание проекта в Google Cloud и получение ключа

Ключ (`google_key.json`) — это «пропуск», по которому программа от имени
служебного (сервисного) аккаунта Google получает доступ к вашей таблице.
Это НЕ ваш личный логин/пароль, а отдельная сущность, которую вы потом
явно «пригласите» в таблицу.

1. Откройте **Google Cloud Console**: https://console.cloud.google.com/
2. Вверху нажмите на выпадающий список проектов → **«Создать проект»**
   (New Project). Дайте любое имя, например `bambu-tracker`. Нажмите «Создать».
3. Убедитесь, что новый проект выбран (вверху страницы).
4. Включите два API, которые нужны программе:
   - Перейдите в **APIs & Services → Library** (Библиотека API).
   - Найдите **Google Sheets API** → откройте → нажмите **Enable** (Включить).
   - Вернитесь в библиотеку, найдите **Google Drive API** → **Enable**.
   (Оба API обязательны: Sheets — для чтения/записи ячеек, Drive — чтобы
   `gspread` мог найти таблицу по имени.)
5. Создайте сервисный аккаунт:
   - **APIs & Services → Credentials** (Учётные данные).
   - **Create Credentials → Service account**.
   - Имя, например `table-writer`. Нажмите **Create and Continue**.
   - Роль можно не назначать (Skip / Continue) — доступ к конкретной таблице
     мы дадим отдельно через «Настройки доступа» самой таблицы.
   - Нажмите **Done**.
6. Создайте ключ для этого сервисного аккаунта:
   - В списке **Service Accounts** откройте только что созданный аккаунт.
   - Вкладка **Keys** → **Add Key → Create new key**.
   - Тип ключа — **JSON**. Нажмите **Create**.
   - Файл `xxxxx.json` автоматически скачается на компьютер.
7. Переименуйте скачанный файл в `google_key.json` (или оставьте как есть —
   имя роли не играет, главное указать правильный путь в настройках) и
   положите его в удобную папку, например рядом с программой.
8. **Важно:** откройте этот JSON и запомните/скопируйте значение поля
   `client_email` — что-то вроде
   `table-writer@bambu-tracker-499411.iam.gserviceaccount.com`.
   Этот адрес понадобится на следующем шаге.

## 4. Шаг 2. Создание Google-таблицы и выдача доступа

1. Зайдите на https://sheets.google.com и создайте новую пустую таблицу.
2. Назовите её так же, как будет указано в настройках программы (по
   умолчанию — **«Учет лаборатории 3D»**). Название должно совпадать
   **дословно**, иначе `gspread` её не найдёт.
3. Нажмите **«Настройки доступа»** (кнопка **Share** справа сверху).
4. В поле «Добавить пользователей и группы» вставьте `client_email` из
   JSON-ключа (шаг 8 предыдущего раздела).
5. Выдайте роль **«Редактор» (Editor)** — без этого программа не сможет
   ни читать, ни записывать данные.
6. Сохраните.

Больше руками ничего создавать не нужно: при первом запуске программа сама
проверит, есть ли листы «Лог печати», «Склад», «Принтеры», и создаст их с
нужными заголовками, если их нет.

---

## 5. Шаг 3. Структура листов таблицы

После первого успешного запуска в таблице появятся (или должны быть
заполнены вручную) три листа:

### Лист «Принтеры» — обязательно заполнить руками для боевого режима
| Название | IP-адрес | Access Code | Серийный номер |
|---|---|---|---|
| Принтер 1 | 192.168.1.50 | 12345678 | 01P00A111111111 |

Без строк на этом листе программа в боевом режиме не подключится ни к
одному принтеру (в тестовом режиме этот лист не используется для
подключения — mock_printers.py сам генерирует данные для всех принтеров,
но лист желательно тоже заполнить, если хотите видеть человеко-читаемые
имена в логе и таблице).

### Лист «Склад» — обязательно заполнить руками
| Тип пластика | Всего закуплено (г) | Потрачено (г) | Остаток на складе (г) | Критический лимит (г) |
|---|---|---|---|---|
| PLA | 5000 | 0 | 5000 | 300 |
| PETG | 3000 | 0 | 3000 | 300 |

- Колонку **«Остаток на складе (г)»** программа читает каждые 5 минут
  (и при старте), чтобы понимать, хватит ли материала на новую печать.
- Программа **не списывает расход автоматически** из этой колонки — это
  сделано намеренно, чтобы вы могли сверять цифры руками/по своей логике
  учёта. Обновляйте «Остаток» самостоятельно (или доработайте формулу
  `Остаток = Всего закуплено − Потрачено` прямо в Google Sheets).
- Если «Остаток» ≤ «Критический лимит» — в лог пишется предупреждение.

### Лист «Лог печати» — заполняется программой автоматически
| Дата и время | Номер заявки | Имя файла | Принтер | Тип пластика | Расход (г) |
|---|---|---|---|---|---|

Трогать руками не нужно — сюда программа сама дописывает строки при каждой
запущенной печати.

## 6. Шаг 4. Установка программы и зависимостей

1. Скопируйте все файлы проекта в одну папку:
   `tracker.py`, `settings_manager.py`, `mock_printers.py`, `google_key.json`.
2. Установите зависимости:
   ```bash
   pip install paho-mqtt gspread
   ```
3. (Только для тестового режима) установите и запустите MQTT-брокер

## 7. Шаг 5. Первый запуск и мастер настройки

При самом первом запуске файла `settings.json` ещё не существует, поэтому
программа автоматически откроет **мастер настройки**:

```bash
python tracker.py
```
(или явно: `python tracker.py --setup`)

В окне мастера заполните:

1. **Файл ключа Google Service Account** — кнопка «Обзор…», выберите
   `google_key.json`, скачанный на шаге 1.
2. **Название таблицы** — должно точно совпадать с названием, которое вы
   дали таблице в Google Sheets (по умолчанию «Учет лаборатории 3D»).
3. **Названия листов** — можно оставить значения по умолчанию («Лог
   печати», «Склад», «Принтеры») или указать свои — тогда именно с такими
   названиями программа будет искать/создавать листы.
4. **Режим работы**:
   - «Тестовый режим (локальный MQTT)» — для проверки, что всё работает,
     без реальных принтеров.
   - «Боевой режим (реальные принтеры)» — для подключения к настоящим
     принтерам по сети.
5. Нажмите **«Сохранить и запустить»**.

Настройки сохранятся в файл `settings.json` рядом с программой, и при
следующих запусках мастер уже не будет открываться автоматически — сразу
запустится мониторинг. Изменить настройки позже можно кнопкой
**«Настройки»** в главном окне.

## 8. Тестовый режим (без реальных принтеров)

Тестовый режим позволяет проверить всю цепочку (MQTT → парсинг → запись в
Google-таблицу → проверка склада) без реальных 3D-принтеров.

### 8.1. Установите и запустите MQTT-брокер Mosquitto

**Windows:**
1. Скачайте установщик: https://mosquitto.org/download/
2. Установите с настройками по умолчанию.
3. Запустите брокер (обычно ставится как служба Windows и стартует сам;
   если нет — запустите `mosquitto.exe` из папки установки, например
   `C:\Program Files\mosquitto\mosquitto.exe`).

**macOS:**
```bash
brew install mosquitto
brew services start mosquitto
```

**Linux (Debian/Ubuntu):**
```bash
sudo apt install mosquitto
sudo systemctl start mosquitto
```

Брокер по умолчанию слушает `localhost:1883` — это именно то, к чему
подключаются и `tracker.py`, и `mock_printers.py` в тестовом режиме.

### 8.2. Запустите симулятор принтеров

В отдельном окне терминала:
```bash
python mock_printers.py
```
Вы должны увидеть в консоли что-то вроде:
```
[ОК] Симулятор запущен. Каждые 7 секунд отправляем лог...
[Принтер 2] Отправил 482_kryshka.gcode | PLA: 120г
```
Симулятор каждые 7 секунд «печатает» случайную деталь на случайном из 4
виртуальных принтеров и публикует это в MQTT.

### 8.3. Запустите саму программу

```bash
python tracker.py
```
Убедитесь, что в настройках выбран **«Тестовый режим»**. В главном окне
должны появляться строки лога вида:
```
[Принтер 2] Заявка 482 добавлена. PLA: 120г
```
и одновременно — новые строки в листе «Лог печати» вашей Google-таблицы.

Если материала на складе не хватает по данным листа «Склад», появится
предупреждение `НЕ ХВАТИТ ПЛАСТИКА!`.

> Заметьте: имена принтеров в mock_printers.py («Принтер 1»…«Принтер 4») и
> их серийные номера — вымышленные и не обязаны совпадать с листом
> «Принтеры» в таблице. Если серийный номер не найден в таблице, в логе
> принтер будет подписан как «Неизвестный (<серийник>)» — это нормально
> для теста.

## 9. Боевой режим (реальные принтеры Bambu Lab)

В боевом режиме программа подключается напрямую к принтерам по MQTT через
TLS (порт 8883), без всякого локального брокера.

### 9.1. Что нужно узнать по каждому принтеру

Для подключения к принтеру Bambu Lab по локальной сети (LAN Mode) нужны
три вещи:

1. **IP-адрес принтера** в вашей локальной сети.
   - На экране принтера: **Настройки → WLAN** (или «Сеть») — там
     отображается текущий IP.
   - Либо посмотрите список подключённых устройств в настройках роутера.
2. **Access Code (код доступа)**.
   - На экране принтера: **Настройки → WLAN → Локальный код доступа**
     (LAN Only Access Code) — 8-значный код.
3. **Серийный номер** принтера.
   - На экране принтера: **Настройки → Сведения об устройстве** (Device
     Info), либо на наклейке на корпусе/коробке (начинается обычно с
     `0`, например `01P00A123456789`).

**Важно:** на принтере должен быть включён **LAN-режим** (LAN Only Mode /
«Режим локальной сети»), иначе принтер не будет публиковать MQTT-сообщения
локально, а Access Code может быть недоступен. Включается в
**Настройки → WLAN → LAN Only Mode**. При включении LAN Only Mode принтер
перестаёт использовать облако Bambu Lab (Bambu Handy может потерять
удалённый доступ) — это ожидаемо, так и должно быть для локального
мониторинга.

### 9.2. Заполните лист «Принтеры» в Google-таблице

Для каждого принтера — одна строка:

| Название | IP-адрес | Access Code | Серийный номер |
|---|---|---|---|
| Bambu X1C №1 | 192.168.1.50 | 12345678 | 01P00A123456789 |
| Bambu P1S №2 | 192.168.1.51 | 87654321 | 01P00A987654321 |

Программа перечитывает этот лист:
- при запуске мониторинга;
- каждые 5 минут автоматически (фоновое обновление);
- сразу после того, как вы измените настройки через кнопку «Настройки».

Поэтому добавить новый принтер можно **прямо в Google-таблице**, без
перезапуска программы — он подключится в течение 5 минут (либо сразу
после нажатия «Настройки → Сохранить»).

### 9.3. Переключите режим на боевой

Откройте кнопку **«Настройки»** в главном окне (или запустите
`python tracker.py --setup` при остановленной программе), выберите
**«Боевой режим (реальные принтеры)»** и сохраните.

Программа начнёт подключаться к каждому принтеру из листа «Принтеры» по
адресу `mqtts://<IP>:8883`, используя логин `bblp` и Access Code в
качестве пароля (это стандартная схема авторизации Bambu Lab MQTT).

В логе вы должны увидеть:
```
[СЕТЬ] Подключен к Bambu X1C №1 (192.168.1.50)
```
Если принтер недоступен — там же появится ошибка подключения (см. раздел
[Troubleshooting](#13-решение-проблем-troubleshooting)).

## 10. Переключение между режимами

1. В главном окне нажмите **«Настройки»**.
2. Переключите радиокнопку **«Тестовый режим»** ↔ **«Боевой режим»**.
3. Нажмите **«Сохранить и запустить»**.

Программа сама остановит текущий мониторинг, перечитает `settings.json` и
запустит мониторинг заново уже в новом режиме — перезапускать сам процесс
`tracker.py` не нужно.

Если после сохранения режим фактически не меняется (в `settings.json`
`test_mode` остаётся `true` при выборе боевого) — убедитесь, что вы
используете исправленную версию `settings_manager.py`/`tracker.py`
(см. предыдущее сообщение в переписке): ранее была ошибка, из-за которой
окно настроек, открытое поверх уже работающей программы, создавало второй
`Tk()`-интерпретатор и значение переключателя считывалось неверно.

## 11. Повседневная работа с программой

Главное окно содержит:

- **Текстовое поле с логом** — в реальном времени показывает события:
  подключения, успешные записи, предупреждения об остатках.
- **«Настройки»** — открыть мастер настройки повторно (сменить ключ,
  название таблицы, листы, режим).
- **«Очистить логи»** — очищает только окно (файл `tracker.log` не
  трогает).
- **«Выход»** — корректно останавливает все MQTT-соединения и закрывает
  программу.

Чтобы **добавить новый тип пластика** — добавьте строку на лист «Склад».
Чтобы **добавить принтер** — добавьте строку на лист «Принтеры» (для
боевого режима также см. раздел 9.1, откуда брать IP/Access Code/серийник).

---

## 12. Логи и что они значат

Все события дублируются в файл `tracker.log` рядом с программой (в
формате `дата - уровень - сообщение`), даже если окно программы закрыто.

Типичные строки:

| Пример строки | Что значит |
|---|---|
| `INFO ... Подключение к Google Таблице успешно.` | ключ и доступ настроены верно |
| `INFO ... Лист 'Склад' создан с заголовками.` | лист не существовал, программа создала его сама |
| `INFO ... [Принтер 2] Заявка 482 добавлена. PLA: 120г` | успешная запись печати в лог |
| `WARNING ... НЕ ХВАТИТ ПЛАСТИКА! ...` | по данным листа «Склад» остатка не хватает на эту печать |
| `WARNING ... КРИТИЧЕСКИЙ ОСТАТОК: PLA осталось 250г (лимит 300г)` | остаток материала опустился ниже критического лимита |
| `ERROR ... Не удалось подключиться к Google Таблице: ...` | проблема с ключом/доступом/названием таблицы — см. Troubleshooting |
| `ERROR ... Не удалось подключиться к <принтер>: ...` | принтер недоступен по сети или неверен IP/Access Code |

## 13. Решение проблем (Troubleshooting)

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| При старте сразу ошибка `Не удалось подключиться к Google Таблице` | Неверный путь к `google_key.json`, либо таблица не расшарена на `client_email`, либо название таблицы не совпадает дословно | Проверьте путь в настройках; убедитесь, что e-mail сервисного аккаунта добавлен в «Настройки доступа» таблицы с ролью Editor; сверьте название таблицы посимвольно |
| `PERMISSION_DENIED` / `403` при обращении к таблице | Не включён Google Sheets API или Google Drive API в Cloud Console, либо сервисный аккаунт не имеет доступа | Включите оба API (шаг 4 раздела 3), проверьте доступ в Share |
| `SpreadsheetNotFound` | Название таблицы в настройках не совпадает с реальным | Откройте таблицу в браузере, скопируйте название точно как оно написано вверху страницы |
| «Нет принтеров в таблице. Добавьте их и перезапустите» | Лист «Принтеры» пуст или в строках отсутствуют нужные колонки | Заполните лист «Принтеры» как описано в разделе 5, названия колонок должны быть ровно: Название, IP-адрес, Access Code, Серийный номер |
| В тестовом режиме нет новых строк в логе | Mosquitto не запущен, либо `mock_printers.py` не запущен | Проверьте, что процесс mosquitto активен (`mosquitto -v` в консоли для отладки), запустите `mock_printers.py` отдельно |
| `Не удалось подключиться к локальному брокеру` | Mosquitto не установлен/не запущен, либо порт 1883 занят/заблокирован фаерволом | Установите и запустите Mosquitto (раздел 8.1), проверьте `telnet localhost 1883` |
| В боевом режиме `Не удалось подключиться к <принтер>` | Неверный IP, принтер выключен/не в той сети, не включён LAN Only Mode, неверный Access Code | Сверьте IP на экране принтера, убедитесь что компьютер и принтер в одной сети, проверьте LAN Only Mode и Access Code |
| Данные не приходят с боевого принтера, хотя подключение есть | Печать не запущена (`gcode_state` не `RUNNING`) — сообщения от принтера приходят, но без активной печати нет данных для записи | Запустите печать и проверьте снова |
| После смены режима в окне настроек `test_mode` в `settings.json` не меняется | Известный баг старой версии со вторым `Tk()`-окном | Используйте исправленную версию `settings_manager.py` и `tracker.py` (см. выше) |
| Окно программы «зависает» на пару секунд при переключении режима | Идёт штатная остановка старых MQTT-соединений (`join(timeout=2)`) | Это нормально, подождите |
| `ModuleNotFoundError: No module named 'gspread'` (или `paho`) | Не установлены зависимости | `pip install paho-mqtt gspread` |
| `ModuleNotFoundError: No module named 'tkinter'` (Linux) | В некоторых сборках Linux tkinter не входит в Python по умолчанию | `sudo apt install python3-tk` |

## 14. Безопасность

- **Никогда не публикуйте `google_key.json`** — это полноценный доступ на
  запись к вашей таблице от имени сервисного аккаунта. Не выкладывайте его
  в открытые репозитории (GitHub) и не пересылайте посторонним.
- Если ключ всё же «утёк» — зайдите в Google Cloud Console → Service
  Accounts → ваш аккаунт → Keys → удалите скомпрометированный ключ и
  создайте новый (шаг 6 раздела 3), обновите путь в настройках программы.
- Access Code принтеров — тоже чувствительная информация (даёт локальный
  доступ к принтеру); лист «Принтеры» в таблице стоит открывать только тем,
  кому это действительно нужно.

## 15. Структура файлов проекта

```
├── tracker.py             # главный файл: GUI + MQTT + запись в Google Sheets
├── settings_manager.py    # мастер настройки (окно, загрузка/сохранение settings.json)
├── mock_printers.py       # симулятор принтеров для тестового режима
├── settings.json          # создаётся автоматически после первого запуска мастера
├── google_key.json        # ключ сервисного аккаунта Google (вы кладёте сюда сами)
└── tracker.log            # файл лога, создаётся автоматически рядом с tracker.py
```
